Installation

Une machine avec Node 22 suffit. Aucune base de données à installer : SQLite vit dans un fichier, et le dossier data/ contient tout ce que l'instance détient.

Démarrage

npm install
npm start          # http://localhost:3000

Sur une instance vierge, toute l'application redirige vers l'assistant d'installation (/installation).

L'assistant, en cinq étapes

  1. Langue — parmi les {{i18n.locales}} disponibles ; devient la langue par défaut de l'instance.
  2. Prérequis — version de Node, dossier de données accessible en écriture, base SQLite, dossier des photos de profil. Deux recommandations de mise en production (TRUST_PROXY, NODE_ENV=production) sont signalées en ambre sans bloquer.
  3. Organisation — nom affiché partout dans l'interface, et quota de congés annuels attribué à chaque nouveau salarié non-freelance.
  4. Administrateur — le premier compte, avec un mot de passe de 12 caractères minimum.
  5. Récapitulatif — vérification puis création de l'instance.

Le tout est écrit en une seule transaction, puis un fichier data/install.lock referme définitivement l'assistant : toute visite ultérieure de /installation renvoie à la page de connexion. Le secret de session est généré automatiquement dans data/session.key (permissions 0600) si SESSION_SECRET n'est pas fourni.

Protéger l'assistant sur un serveur exposé

La fenêtre avant votre propre installation

Entre la mise en ligne et votre première connexion, n'importe qui atteignant le serveur peut dérouler l'assistant à votre place et devenir administrateur.

Définissez INSTALL_TOKEN avant le premier démarrage : l'assistant réclame alors ce jeton à l'étape des prérequis. 

INSTALL_TOKEN=un-jeton-long-et-aleatoire npm start

Installation sans interface

Pour un déploiement automatisé, renseigner ADMIN_EMAIL et ADMIN_PASSWORD crée le compte administrateur au démarrage ; l'instance est alors considérée comme installée et l'assistant ne s'ouvre pas. 

cp .env.example .env      # ADMIN_EMAIL / ADMIN_PASSWORD / SESSION_SECRET
npm start

Jeu de démonstration

node scripts/seed-demo.js

Cinq membres rattachés, outils, demandes, paie, pointages, actualités et messages. Tous les comptes partagent le mot de passe demo-1234, dont claire.moreau@entreprise.com (responsable RH) et lucas.petit@entreprise.com (freelance).

Jamais en production

Ces comptes ont un mot de passe public. Le jeu de démonstration sert à explorer l'application, pas à démarrer une instance réelle.

Mise en production

Trois réglages transforment une instance de développement en instance exploitable :

  • NODE_ENV=production — active les cookies sécurisés, les vérifications de secrets au démarrage et le cache statique.
  • TRUST_PROXY=1 — derrière un reverse proxy, pour que la limitation de débit voie la vraie adresse du client et non celle du proxy.
  • SESSION_SECRET et ADMIN_PASSWORD — le serveur refuse de démarrer en production s'ils sont restés à leur valeur par défaut.

Le dossier data/ doit être sauvegardé et recopié hors du serveur : voir Sauvegardes, qui automatise l'un et l'autre.

Mise à jour depuis une version antérieure

Les instances créées avant l'introduction des services et des équipes sont reprises automatiquement au premier démarrage, une seule fois :

  • chaque libellé de service saisi en texte libre devient un service ;
  • chaque encadrant devient le manager d'une équipe portant ses anciens collaborateurs ;
  • les actualités d'équipe suivent l'équipe de leur auteur.

Les colonnes users.department, users.manager_id et announcements.team_manager_id sont ensuite retirées. Aucune action n'est requise ; sauvegardez simplement data/ avant la mise à jour, comme pour toute migration.
