설치

Toutadmin 설치하기

같은 제품의 두 에디션: 하나는 서버에서 서비스로 실행되고, 다른 하나는 공유 호스팅에 올립니다. 필수 데이터베이스도, 외부 서비스도 없습니다 — MySQL 서버가 있으면 사용합니다. 마법사를 열어 써 보는 데 5분, 서비스·HTTPS·백업을 갖춘 완전한 운영 시작에 1시간입니다.

무료 인스턴스 신청하기 제품 내려받기

유럽에서 호스팅, 설치할 것 없음: 직원 다섯 명까지 무료, 첫날부터 제품 전체. 직접 열어 드리고 준비되는 대로 연락드립니다.

내려받기는 누구에게나 열려 있습니다

무료 형태는 SaaS에서 끝나지 않습니다. 다섯 사람까지라면 제품을 자기 자리에 두어도 —— 자기 파일, 자기 데이터베이스, 자기 백업 —— 한 푼도 들지 않습니다. 형태를 정하는 것은 인원 수이지, 인스턴스가 어디서 도는가가 아닙니다. 다섯 사람을 넘으면 구독이 필요하며, 인스턴스가 저희 쪽에서 돌든 그쪽에서 돌든 마찬가지입니다.

무엇을 설치할까

기능이 아니라 호스팅 환경이 선택을 결정합니다. 두 판본이 하는 일은 완전히 같습니다.

Node 판

직접 관리하는 서버용: 기계 한 대, 상시 도는 서비스, 그 앞의 역방향 프록시.

Node 22, C 컴파일러, 로컬 디스크. 수십 명 규모라면 1코어로 충분합니다. MySQL 서버가 있으면 그것을 쓰고, 없으면 SQLite가 아무것도 요구하지 않습니다.

PHP 판

공용 호스팅용: 올릴 폴더 하나, 채울 파일 하나, 예약 작업 하나. 명령줄은 필요 없습니다.

PHP 8.1과 SQLite 확장. 설치할 의존성은 없습니다. Composer도, 패키지 관리자도 필요 없습니다. 데이터베이스 서버를 원한다면 PDO MySQL 확장도 함께.

선택은 되돌릴 수 있습니다

두 판본은 같은 데이터베이스 구조와 같은 비밀번호 형식을 씁니다. 옮기는 일은 데이터베이스 파일 하나와 폴더 다섯 개를 복사하는 것뿐입니다. 변환 과정도 없고, 누구도 비밀번호를 바꿀 필요가 없습니다.

SQLite 또는 MySQL

그러면 어떤 데이터베이스인가

두 번째 선택이자, 바꾸기 어려운 유일한 선택입니다. 판본과는 무관합니다. 두 판본 모두 두 엔진을 받아들이고, 네 조합이 같은 시험을 통과합니다.

SQLite

서버 디스크 위의 파일 하나. 설치할 것도, 관리할 것도, 지켜볼 것도 없습니다 — 인스턴스는 폴더 하나를 복사해 옮깁니다.

기본값이며 대부분의 경우 옳은 답입니다. 응용 서버 한 대와, 배포를 넘어 남는 로컬 디스크가 있다면.

MySQL 또는 MariaDB

데이터베이스 서버. 같은 기계에 두어도, 망의 다른 곳에 두어도 됩니다. 데이터는 전산 부서가 이미 백업하고 복제하고 감시하는 곳에 삽니다.

세 가지 이유로 고릅니다. 같은 데이터베이스에 여러 응용 서버, 그것을 요구하는 내부 규정, 또는 휘발성 응용 디스크 — 배포마다 새로 짓는 컨테이너.

MySQL은 속도를 위한 선택이 아닙니다

가장 널리 퍼진 믿음이고, 틀렸습니다. SQLite는 프로세스 안에, MySQL은 소켓 너머에 삽니다. 저희가 이천 번의 연산으로 재어 보니 SQLite가 연산에 따라 2.5배에서 150배 빨랐고, 여덟 명이 동시에 쓰는 경우에도 비교를 견뎌 냈습니다. MySQL은 데이터가 어디에 살고 누가 관리하느냐 때문에 고르는 것이지, 응답 시간 때문이 아닙니다.

세 갈래, 하나의 마법사

엔진 세우기

Docker, Linux 스크립트, Windows 스크립트. 셋 모두 같은 곳에서 멈춥니다 — 브라우저의 마법사 앞입니다. 어느 것도 데이터베이스, 관리 계정, 라이선스를 만들지 않습니다. 그것은 마법사가 아홉 단계로 하고, 그다음 스스로 닫힙니다.

컨테이너에서

에디션마다 이미지 하나, 데이터에는 볼륨 하나. 이미지를 몇 번 바꾸어도 인스턴스는 그대로이며, 라이선스도 함께 남습니다.

docker compose up -d
# puis http://localhost:3000

리눅스 서버에서

apt, dnf 또는 apk. 스크립트가 엔진과 시스템 사용자, 스스로 다시 뜨는 서비스를 세우고, 도메인을 주면 리버스 프록시와 인증서까지 갖춥니다.

sudo ./deploiement/install.sh \
  --domaine intranet.exemple.fr \
  --courriel vous@exemple.fr

윈도우에서

Node는 설치 관리자가 아니라 압축 파일로 내려받습니다. 버전이 고정되고 컴파일러가 필요 없습니다. 작업이 컴퓨터와 함께 시작됩니다.

# PowerShell, en administrateur
.\deploiement\install.ps1

스크립트나 이미지로 세운 인스턴스는 스스로 갱신하지 않습니다

의도한 바입니다. 컨테이너 안에서 덮어쓴 파일은 그것을 처음 교체할 때 사라집니다 — 갱신은 된 것처럼 보이다가 혼자 풀려버립니다. 「업데이트」 화면은 새 버전을 계속 알리되, 단추 대신 할 일을 알려 줍니다. 이미지를 바꾸거나, 스크립트를 다시 실행하십시오.

빠른 설치

마법사를 열기에 딱 필요한 만큼. 자세한 것은 바로 뒤에, 한 걸음씩 —— 어떤 명령이 무엇을 왜 하는지와 함께.

Node 판

직접 관리하는 서버에서 명령 셋. 마지막 명령이 설치 토큰을 만들고 인스턴스를 띄웁니다.

git clone -b node \
  https://repo.qu3ntin.com/toutadmin/toutadmin.git
cd toutadmin && npm ci --omit=dev
INSTALL_TOKEN=$(openssl rand -hex 16) \
NODE_ENV=production node src/server.js

PHP 판

명령줄은 전혀 없습니다. 올려 둘 폴더 하나, 복사할 파일 하나, 열어 줄 쓰기 권한 하나.

# 1. le code, ou l'archive (racine → public/)
git clone -b php \
  https://repo.qu3ntin.com/toutadmin/toutadmin.git
# 2. cp config.sample.php config.php
# 3. chmod 770 data/
# 4. ouvrir https://votre-domaine/install

나머지는 마법사가 합니다

인스턴스는 빈 채로 떠서 스스로를 닫습니다. 설치가 끝나기 전에는 어떤 주소든 마법사로 가고, 끝나는 순간 마법사는 영영 사라집니다.

  1. 1 언어인스턴스의 언어를 열여섯 가운데서. 나중에 바꿀 수 있고, 각자는 제 언어를 지닙니다.
  2. 2 선행 조건마법사가 제 발밑을 살핍니다. 판, 쓰기 권한, 데이터베이스, 폴더. 없는 것은 이름을 대지, 짐작하지 않습니다.
  3. 3 업데이트무엇이든 설치하기 전에 더 새로운 것이 없는지 확인합니다. 오래된 버전으로 시작하는 것은 좋은 출발이 아닙니다.
  4. 4 라이선스마법사가 고객 공간에서 가져오는 활성화 키, 또는 클릭 한 번으로 받는 무료 라이선스. 없이 진행하고 나중에 활성화할 수도 있습니다.
  5. 5 데이터베이스아무것도 요구하지 않는 파일 하나짜리 SQLite, 또는 가지고 계시다면 MySQL / MariaDB. 마법사는 몸을 맡기기 전에 연결을 시도합니다.
  6. 6 조직회사 이름과 한 해 휴가 일수. 답 둘, 나중에 고칠 수 있습니다.
  7. 7 섹션설치하는 업무 영역입니다. 설치하지 않은 섹션은 아무것도 보여 주지 않으며, 나중에 체크 하나로 추가할 수 있고 그 데이터는 기다리고 있습니다.
  8. 8 관리자첫 계정. 최소 열두 글자: 다른 계정을 만들 수 있는 유일한 계정입니다.
  9. 9 설치요약을 보이고, 화면에 알리는 네 단계로 설치합니다. 마법사는 그대로 영영 닫힙니다.

포트를 열기 전에 설치 토큰을 두십시오

처음 띄운 때부터 당신이 마법사를 지나기까지, 먼저 온 사람이 관리 계정을 만들어 버립니다. INSTALL_TOKEN이 그 창을 닫습니다. 그것이 없으면 마법사는 열리기를 거부합니다.

설치 마법사
Node 판

자체 서버에서, 네 단계

  1. 내려받아 설치하기

    npm install이 아니라 npm ci를 쓰십시오. 잠금 파일이 적은 그대로 설치합니다. 서버에서 슬쩍 어긋난 버전은 아무도 이유를 모르는 장애가 됩니다.

    git clone -b node \
  https://repo.qu3ntin.com/toutadmin/toutadmin.git /var/www/toutadmin
cd /var/www/toutadmin
npm ci --omit=dev

  2. 설정하기

    모든 설정은 환경 변수로 하며, 필수 항목은 하나도 없습니다. 포트를 열기 전에 INSTALL_TOKEN을 두십시오. 첫 구동부터 설치 마법사에 들어가기까지 사이에는 먼저 온 사람이 관리자 계정을 만들 수 있습니다.

    cp .env.example .env
# PORT, NODE_ENV=production, INSTALL_TOKEN…

  3. 시스템에 맡기기

    손으로 띄우면 터미널을 닫는 순간 멈춥니다. 서비스는 스스로 다시 일어나고, 자기 데이터 폴더에만 쓸 수 있습니다.

    sudo systemctl enable --now toutadmin
journalctl -u toutadmin -f

  4. 연결 암호화하기

    응용 포트를 인터넷에 그대로 내놓지 마십시오. 프록시 뒤에서 본체가 보안 헤더를 직접 붙입니다. HSTS도 포함되며, 이미 암호화된 연결에서만 붙입니다.

    sudo certbot --nginx -d intranet.exemple.fr

    git clone -b php \
  https://repo.qu3ntin.com/toutadmin/toutadmin.git /var/www/toutadmin
# ou l'archive ; la racine web pointe sur public/, pas sur le dossier

  2. 설정 적기

    설정은 마법사가 쓰며, 그것도 맨 마지막에 씁니다. 파일이 없는 한, 중단된 설치는 아무것도 남기지 않은 것입니다. 거기에 인스턴스 고유의 키를 넣습니다. 서명을 봉인하고 데이터베이스의 비밀을 암호화하는 키이니, 나머지와 함께 백업해 두세요.

    cp config.sample.php config.php
php -r "echo bin2hex(random_bytes(32));"   # session_secret

  3. 쓰기 권한 열기

    SQLite는 데이터베이스 옆에도 파일을 씁니다. 쓸 수 있어야 하는 것은 폴더이지 파일만이 아닙니다. 제품의 나머지는 읽기 전용으로 두어도 됩니다.

    chmod 770 data/     # le dossier, pas seulement la base

  4. 정기 작업 걸기

    PHP 사이트는 요청이 있는 동안에만 살아 있습니다. 예약 작업이 만료된 계약을 닫고, 반복 청구서를 발행하고, 웹훅을 보내고, 백업을 만듭니다.

    * * * * * /usr/bin/php /var/www/toutadmin/tools/cron.php

동료에게 열기 전에

건물 밖으로 나가는 백업

데이터베이스가 작을 때 곧바로 하나 만들고, 원격 보관처를 설정하십시오. 지켜야 할 서버에 그대로 남은 보관 파일은 아무것도 지키지 못합니다.

권한 없는 시험 계정

그 계정으로 로그인해 둘러보십시오. 동료의 눈으로 제품을 보는 유일한 방법이자, 가장 자주 건너뛰는 점검입니다.

관리자는 한 명이 아니라 두 명

이중 인증을 켠 뒤 휴대전화와 복구 코드를 함께 잃으면, 문을 열어 줄 수 있는 사람은 다른 관리자뿐입니다. 뒷문은 없습니다.

전체 안내는 문서에 있습니다

이 문서는 줄거리만 보여 줍니다. 나머지는 모두 문서에 있습니다. 앞단 서버 설정, 정확한 권한, 인증서, 복원, 갱신, 증상별 문제 해결 — 그리고 판본마다 하나씩, 두 안내서의 전문입니다.
